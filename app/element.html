One tag, and the customer checks it themselves.

A vendor showing “your booking was confirmed” is asking to be believed. This element does not ask. It resolves every key from the origin that signed the statement and verifies in the visitor’s own browser — it never contacts the coordinator that produced the receipt.

About this page. The two receipts below are generated here, in your browser, with keys that exist for a few milliseconds and that no origin publishes — so the element is handed a matching resolver instead of fetching over TLS, and it says so in its own footer rather than claiming an origin check it did not do. Everything else is the shipped element. For a receipt with real signatures from the real participants, use the verifier origin or npx concord-verify. 

<script type="module" src="https://unpkg.com/concord-verify/concord-receipt.mjs"></script>

<concord-receipt src="/receipts/RH-9.json"></concord-receipt>
